# XLSX Fixtures — Manifest

This directory holds XLSX files used by tests and demos.

## Synthetic (`./synthetic`)

These are **synthetic** workbooks generated by
`scripts/generate-xlsx-fixtures.mjs` using
[SheetJS Community Edition](https://sheetjs.com) (Apache 2.0). They are
deterministic and small (8–135 KB) and are checked in so tests are
hermetic.

Regenerate with:

```bash
pnpm fixtures:xlsx
```

| File                           | Size    | What it exercises                                                                                                      |
| ------------------------------ | ------- | ---------------------------------------------------------------------------------------------------------------------- |
| `01-single-sheet-numbers.xlsx` | ~9 KB   | One sheet, mixed value kinds (string / int / float / boolean / blank). Smallest happy path.                            |
| `02-multi-sheet.xlsx`          | ~11 KB  | Three sheets (Sales, Expenses, Summary) with cross-sheet formula references like `=Sales!B2-Expenses!B2`.              |
| `03-formulas-basic.xlsx`       | ~10 KB  | `SUM`, `AVERAGE`, `COUNTIF`, `MAX`, `IF`, `VLOOKUP` — drives the P0 function categories listed in `formula-engine.md`. |
| `04-merged-and-formatted.xlsx` | ~10 KB  | Merged title row, header fill, currency + percent number formats, custom column widths and row heights.                |
| `05-comments-hyperlinks.xlsx`  | ~12 KB  | Cell comments (with author + body), tooltip-bearing hyperlinks, plain hyperlinks. Exercises the comments+rels parts.   |
| `06-large-grid.xlsx`           | ~133 KB | 1,000 × 7 grid with mixed types — perf smoke (under the 1 s parse / 16 ms scroll budget in `acceptance-criteria.md`).  |

These cover the **shapes** we model in P0; they are not a substitute for
real-world workbooks emitted by Excel/LibreOffice/Google Sheets (see
below).

## To-Collect Real-World Slots (`./real-world/`)

The synthetic fixtures above are the floor, not the ceiling. The
following slots reserve room for genuine workbooks emitted by real
Excel / LibreOffice / Google-Sheets / Numbers installs — they cover the
long-tail XML quirks those producers add (rich themes, pivot caches,
slicer parts, drawing relationships, custom XML, VBA projects) that a
clean third-party emitter can't fully reproduce. Each should be a
small, license-clean workbook we can check in (or a script that fetches
a public-domain workbook into `./real-world/.cache/` at test time):

| Slot                               | Source                            | Why we need it                                                                                              |
| ---------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `real-excel-2021-budget.xlsx`      | Microsoft Excel for Windows       | Verify our parser tolerates the dense "Excel default" XML (rich themes, table parts, full styles).          |
| `real-excel-mac-2021-pivot.xlsx`   | Microsoft Excel for Mac           | Pivot tables — caches, definitions, slicers — must round-trip byte-clean as opaque parts.                   |
| `real-excel-charts.xlsx`           | Excel with line + bar + pie       | `xl/charts/`, `xl/drawings/`, `xl/embeddings/` — preserve through round-trip; renderer falls back to image. |
| `real-libreoffice-7-report.xlsx`   | LibreOffice Calc                  | LibreOffice uses different namespace prefixes; emits some attributes in different orders.                   |
| `real-google-sheets-export.xlsx`   | Google Sheets "Download as .xlsx" | Google's exporter has its own quirks (theme handling, named ranges).                                        |
| `real-numbers-export.xlsx`         | Apple Numbers export              | Numbers exports include non-standard relationships and custom XML chunks.                                   |
| `real-vba-macros.xlsm`             | Excel with VBA project            | Verify `xl/vbaProject.bin` survives round-trip untouched (we never execute it).                             |
| `real-conditional-formatting.xlsx` | Excel with color scales + bars    | Verify conditional-format rules survive byte-clean even though P0 only authors cell-value rules.            |
| `real-tables-listobjects.xlsx`     | Excel with named table            | `xl/tables/` parts — preserve through round-trip; not modeled in P0.                                        |
| `real-comments-threaded.xlsx`      | Excel with threaded comments      | `xl/comments*.xml` + `xl/threadedComments/` — verify the comment graph and rels stay aligned.               |
| `real-defined-names.xlsx`          | Excel with workbook + sheet names | `<definedName>` entries with both global and sheet-local scope.                                             |
| `real-data-validation.xlsx`        | Excel with dropdown validation    | `<dataValidations>` — preserve through round-trip; not authored in P0.                                      |

> **Reproduction policy.** Real-world fixtures must be
>
> - either created by us in Excel / LibreOffice for the project (preferred), or
> - drawn from a clearly public-domain / CC0 source.
>
> Do not commit copyrighted samples even if they look "innocuous". When in doubt,
> add a `.gitignore` entry and document a one-liner that fetches the workbook on
> demand.

## How fixtures are used

- `packages/xlsx/src/parser/parse.test.ts` and
  `packages/xlsx/src/serializer/serialize.test.ts` use **synthetic XML**
  (not these zip files) so the tests stay sub-millisecond. The fixtures
  here are the next layer: they run the full container path
  (`OoxmlContainer.load → parseXlsx → serializeXlsx → reload`).
- `tests/roundtrip/xlsx/` (top-level integration tests, landing in
  Phase 4) iterates this directory and asserts `untouched parts are
byte-identical`.
- The web demo bundles the smallest fixture
  (`01-single-sheet-numbers.xlsx`) inline so the editor host can boot a
  workbook without a network fetch.
